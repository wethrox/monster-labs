# Beast Builder Lab: Phase 1 MVP

Design and architecture: [docs/GAME_DESIGN.md](docs/GAME_DESIGN.md).

## Getting it into Roblox Studio

**Option A: open the built place.** Open `BeastBuilderLab.rbxl` in Studio. The world, UI and remotes are all
generated by scripts at runtime, so the place has no hand-built parts.

**Option B: Rojo live sync** (recommended for development):
```bash
rojo serve
```
Then connect from the Rojo Studio plugin. To rebuild the place file, run `rojo build -o BeastBuilderLab.rbxl`.

**To save progress in Studio:** publish the place, then turn on *Game Settings → Security → Enable Studio Access to API
Services*. Without that, the server prints a `MEMORY MODE` warning and nothing persists. Everything else still works.

## What is implemented
- 10 data-driven slots and 41 parts across 6 rarities. Socket-based assembly works for any combination of parts.
- Builder: live 3D preview (drag/zoom), part picker with ownership counts, live stats and $/s, compatibility
  (required slots, Horns→Head, Claws→Arms), Auto-Fill, naming, edit mode, blueprint save and share codes.
- **Universal passive income:** one server loop pays every owned monster every second, including during battles.
  Offline earnings run at 50%, capped at 8 h, from server time, with a welcome-back popup.
- Hybrid arena combat: the server-side sim runs at 10 Hz. There are 5 arenas. Ability button (Space / tap / gamepad X) with a
  3 s auto-cast. Enemy wind-ups are telegraphed. Wins give rewards, first-win bonuses, unlocks and part drops.
- Economy: level upgrades, crates, part shop, lab income tiers, containment pod (slot) tiers.
- Persistence: UpdateAsync, session locking, autosave every 120 s, saves on leave and BindToClose.
- Security: whitelisted actions, payload type checks, token-bucket rate limiting, all values computed on the server.
- Lab world: 8 player plots with pedestals showing your top 6 monsters, a live income sign, and a hub with the arena and shop.
- Tutorial covering the first three minutes. Its progress is saved on the server.

## Not implemented yet (later roadmap phases)
Rebirth, 2v2 / matchmaking (BattleSim already supports N-vs-N), shared labs, daily quests and login rewards,
collection index, Motor6D animation rigs, sound/VFX, game passes and dev products, and a phone-specific layout.

## In-Studio test checklist
Use **Play** (1 player), then **Test → Clients and Servers** with 2 players for the multiplayer checks.

1. **Boot:** the Output shows no errors. You spawn on a plot and the sign shows "<you>'s Lab".
2. **Tutorial and build:** the banner says to open the Builder. Click 🧬 Build, then Auto-Fill, then BUILD. The toast
   says "+$5.0/s", the HUD shows `+$5.0/s` and the money counter climbs. Your monster appears on pedestal 1.
3. **Income keeps running during combat:** note the money, start Practice Pit, and watch the HUD (still visible above the
   battle) rise by about $5/s during the fight. Win to get $180 (first win ×3), 25 XP and Spiky Horns.
4. **Upgrade:** 📦 Monsters → ⬆ ($125). The HUD should go to $5.75/s and the tutorial completes.
5. **Edit:** Edit → Horns → Spiky Horns → Save Changes. Income rises by about $0.58/s (0.5 × the level-2 bonus) and the part count drops to x0.
6. **Duplication checks:** open the Developer Console (F9), switch to the client, and run
   `print(game.ReplicatedStorage.Remotes.Action:InvokeServer("BuildMonster", {parts={Torso="torso_chimera",Head="head_lion",Legs="legs_titan"}}).err)`.
   It should print "You don't own Chimera Core Body". Run it 30 times in a loop and some calls should return "Slow down!".
7. **Recycle:** press it twice. The parts come back and income drops.
8. **Ability:** in Goblin Gutter, press Space when the button is ready. The ability fires early. If you leave it alone,
   it auto-fires 3 s after it's ready.
9. **Persistence** (API access on): earn money, stop, wait 2+ minutes, then Play again. You should see the welcome-back popup with
   about 50% × rate × time away, and your monsters and parts should still be there.
10. **Multiplayer:** with 2 clients, each gets their own plot and pedestals, and battles only appear for the player fighting.

## Tuning
All balance numbers are in `src/shared/Config.lua`, `PartCatalog.lua` and `Arenas.lua`.
Formulas are in `Stats.lua` and `BattleSim.lua`. Both are pure modules, so you can balance-test from the
command bar, e.g.:
```lua
local S = game.ReplicatedStorage.Shared
local Stats, Sim, Arenas = require(S.Stats), require(S.BattleSim), require(S.Arenas)
local me = Stats.compute({Torso="torso_goblin",Head="head_goblin",Legs="legs_runner",Arms="arms_brawler"}, 3)
local a = Arenas[2]; local foe = Stats.compute(a.enemy, a.level); foe.hp *= a.scale; foe.atk *= a.scale
local wins = 0
for i = 1, 200 do
  local sim = Sim.new({{team=1,name="me",stats=me,controlled=true},{team=2,name="foe",stats=foe}})
  if sim:runToEnd() == 1 then wins += 1 end
end
print("win rate", wins / 200)
```
